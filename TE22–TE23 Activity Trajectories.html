Summary

What to check against your results

Counts differ? Check events without a URL first

File edits, inline runs, and compile and runtime errors in 2023/24 carry no page of their own. They get a unit only if you take it from the page the student was on. In the long file, n_direct and n_from_context separate the two. Context accounts for 32% of all events. When I hid the URLs that TE23 errors do carry, the page context recovered the same unit for 99.8% of them.

No natural number of states

BIC improves with every extra profile, and the profiles are levels of one activity continuum. The chapter's rule (BIC elbow plus entropy) picks model 1 with 3 states. On log counts that gives Low 3% / Medium 25% / High 72%, where Low is mostly zero-activity units. On raw counts, as the chapter's recipe reads literally, the shape flips to 69% / 27% / 4%. Model 2 fits better at every number of states. Its 4-state solution (6 / 22 / 38 / 35%) is the one I would use for “high, medium, low”.

Same shapes, different students

Students' relative activity is fairly stable from unit to unit (ICC 0.50), so trajectories mostly sort students by overall level. The same three shapes recur across definitions: high throughout, a middle group that moves between neighbouring states, and a lower group. In 13 of the 14 definitions, that lower group drops further after the first three units and partly recovers for the final project. Who lands where changes a lot: the 3-trajectory partitions of the 14 definitions agree at a median ARI of 0.28.

Ward on LCS depends on row order

LCS distances are whole numbers with many ties, and hclust(…, "ward.D2") breaks ties by position. For model 1 / 3 states / 3 trajectories, only 1.2% of 500 shuffled row orders reproduced the partition. The median ARI with the original order was 0.80, and 10% of orders fell below 0.47. Trajectories here are consensus solutions over 500 orders. Run the check in section 5 on your own solution.

Part of it is a class effect

With model 1 / 3 states, 2 of 27 te22a students are in the high-throughout trajectory, compared with 21 of 32 in te22b (χ² p < 0.001). States are relative to all 159 students, so class-level differences in how much was assigned feed straight into the trajectories. Standardising within unit × class is the alternative to try.

Weak cluster structure

Average silhouette width is 0.35 for the 3-trajectory solution on model 1 / 3 states and 0.27 on model 2 / 4 states, both in the 0.26–0.50 “weak structure” band. Describe the trajectories as bands on a continuum rather than distinct types.

Step 0 · Event counts per unit

Every event gets a unit from its exercise, its notes page, or the page the student was on

TE22 events come from te22.csv.gz (Aug 2023–Jun 2024). TE23 events come from te23.csv.gz between 1 Aug 2024 and 31 Jul 2025. I dropped 4,128 events: TE22 students' activity in the 2024/25 file, and TE23 activity after July 2025. Student and class come from cs_anon_to_SCT.csv. One te23b student in that file (10005914) has no events.

  • Exercises. The ID in /exercise/<id> or in exercise_id on autograde events is looked up in the exercise info. The unit is the first number of the name for course cs1-22: 515 exercises, units 1–12, with unit 12 holding the final project. Exercises from cs0 and cs2-22 count as another course.
  • Lesson notes. Notes IDs 2695–2945 are split into units by ID range. The ranges contain the collection IDs of every cs1-22 exercise in the matching unit. On notes_* events, exercise_id is the question number inside the page, not an exercise.
  • Everything else. The event takes the location of the student's last located event, if it was within 30 minutes. This covers file edits, inline runs, errors in 2023/24, resets and settings. A second count written separately, using merge_asof, reproduces all 49,608 cells of the long file.

Step 1 · Variables → states

Activity per unit is one continuum, and LPA cuts it where the tails are

Indicators. Four counts per student and unit: code runs (run_code_exercise), code edits (file_edit), page views (pageview), and lesson-notes work (notes_correct + notes_incorrect + run_code_inline). Each is log(1 + count), z-scored within unit across all five classes, the same way the chapter standardises within course. Runs and edits correlate at 0.90, and both correlate with page views at 0.67–0.68. Lesson-notes work correlates 0.32–0.47 with the others.

Models. mclust 6.0.1, which tidyLPA calls: models 1, 2, 3 and 6 (EEI, VVI, EEE, VVV), with 1–8 profiles and mclust's default start. Model 3 leaves profiles empty from 4 profiles up. Model 6 has the lowest BIC but entropy of only 0.52–0.71. That leaves models 1 and 2.

Steps 2 and 3 · States → sequences → trajectories

Trajectory explorer

Each student's 12 states form one sequence in curriculum order. Every class worked through the units in order, from August to May. Distances are LCS, as in the chapter: TraMineR's seqdist(method = "LCS"), which is |x| + |y| − 2·LCS. Trajectories are Ward clusters (hclust(…, "ward.D2") in R), pooled over 500 random row orders. T1 is always the most active trajectory.

Checking your own run

Three checks to run on your analysis

  1. Row-order sensitivity. Re-cut your Ward tree on shuffled rows and see how often you get the same trajectories back. If the median ARI is well below 1, report a consensus or a stability measure with the trajectories.
  2. Cross-tabulate memberships with mine. vasstra_student_results.csv has each student's sequence and consensus trajectory (2–5) for all 14 definitions, keyed by user_id. Pick the definition closest to yours. Between my own definitions the median ARI is 0.28, so a value in that range does not mean either analysis is wrong.
  3. Precarity state order. TraMineR's seqprecarity reads state.order (by default the alphabet order) as ranking states from most to least desirable. With alphabetical labels such as High, Low, Medium, that order is wrong. Pass state.order = c("High", "Medium", "Low") through prec.args.
# 1. Does your Ward solution depend on the row order?
d    <- seqdist(clus_seq, method = "LCS")
base <- cutree(hclust(as.dist(d), method = "ward.D2"), k = 3)
set.seed(1)
ari <- replicate(200, {
  p  <- sample(nrow(d))
  cl <- integer(nrow(d))
  cl[p] <- cutree(hclust(as.dist(d[p, p]), method = "ward.D2"), k = 3)
  mclust::adjustedRandIndex(base, cl)
})
summary(ari); mean(ari > 0.999)   # share of orders that give the same partition

# 2. Your trajectories against mine (pick the column closest to your setup)
mine <- read.csv("vasstra_student_results.csv")
m    <- merge(data.frame(user_id = your_ids, yours = grouping), mine, by = "user_id")
table(m$yours, m$lpa_k3_traj3)
mclust::adjustedRandIndex(m$yours, m$lpa_k3_traj3)
Methods and limits

Decisions behind these numbers

  • Classes come from cs_anon_to_SCT.csv: te22b = user IDs 10003959–10003990, te22c = 10003926–10003958. The earlier activity-cluster analysis had these two labels the other way round, though its group memberships were the same.
  • States are numbered from lowest to highest mean activity and named by rank: Low, Medium, High (Very low and Very high for 4 and 5 states). The Low state of model 1 is almost all zero-activity units; the names describe rank, not size.
  • Consensus trajectories: Ward was run on 500 random row orders. For each pair of students I counted how often they shared a cluster, and cut an average-linkage tree on 1 minus that share. Membership confidence is a student's mean co-assignment with the rest of their trajectory.
  • Quality statistics (PBC, HG, HGSD, ASW, ASWw, CH, R2, CHsq, R2sq, HC) follow WeightedCluster and come from the port in the Python package sequenzo 0.1.42. ASW, CH and R2 match my own implementation exactly.
  • Sequence indices: transitions, entropy, complexity, volatility and integrative capacity follow TraMineR's definitions, with the highest state as the positive state. I checked them against sequenzo. Precarity follows seqprecarity's defaults (TRATEDSS, otto 0.2, a 1, b 1.2, states ordered from highest to lowest). TraMineR could not be installed here, so I re-implemented it; treat precarity as approximate.
  • Discriminating subsequences are an approximation of seqefsub / seqecmpgroup: the start state plus one event per state change, ordered pairs up to length 2, support ≥ 5%, χ² across trajectories.
  • Software: R 4.3.3 with mclust 6.0.1; Python with pandas, SciPy, scikit-learn and sequenzo. The scripts are in the project under claude/vasstra/, and run_all.sh runs everything in order.

Files: unit_event_counts_long.csv and unit_event_counts_wide.csv (counts), vasstra_student_results.csv (states and trajectories per student). This page shows no student names or IDs; the results file does, so keep it with the rest of your data.
