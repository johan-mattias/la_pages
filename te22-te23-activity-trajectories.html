VaSSTra re-analysis · CMU CS Academy event logs · 2023/24 and 2024/25

Activity across the units

The VaSSTra steps (variables → states → sequences → trajectories) applied to the TE22 and TE23 logs: each student's activity in a unit becomes a state, the states over the units a sequence, and the sequences are grouped into trajectories. Every number on this page comes from the event counts per student and unit.

Summary

Findings

A third of events take their unit from context

File edits, inline runs, and compile and runtime errors in 2023/24 carry no page of their own, so they get a unit from the page the student was on. That context accounts for 32% of all events. As a check, TE23's errors, which do carry a URL, were also placed from context alone: the page context recovered the same unit for 99.8% of them.

No natural number of states

BIC improves with every extra profile, and the profiles are levels of one activity continuum. The book chapter's rule (BIC elbow plus entropy) picks model 1 with 3 states. On log counts that gives Low 3% / Medium 25% / High 72%, where Low is mostly zero-activity units. On raw counts, as the book chapter's recipe reads literally, the shape flips to 69% / 26% / 4%. Model 2 fits better at every number of states. Its 4-state solution (6 / 21 / 38 / 35%) is the better basis for “high, medium, low”.

Same shapes, different students

Students' relative activity is fairly stable from unit to unit (ICC 0.50), so trajectories mostly sort students by overall level. The eight raw-count, within-unit × class definitions let us compare the same 2–5 state choices under model 1 (EEI) and model 2 (VVI). Who lands where changes across definitions, so the explorer reports each solution rather than treating one state count as definitive.

Ward on LCS depends on row order

LCS distances are whole numbers with many ties, and hclust(…, "ward.D2") breaks ties by position. For model 1 / 3 states / 3 trajectories, only 4.0% of 500 shuffled row orders reproduced the partition. The median ARI with the original order was 0.86, and 10% of orders fell below 0.27. Trajectories here are consensus solutions over 500 orders, and any Ward solution on LCS distances needs the same check.

Part of it is a class effect

With model 1 / 3 states, 2 of 25 te22a students are in the high-throughout trajectory, compared with 18 of 30 in te22b (χ² p < 0.001). States are relative to all 153 students, so class-level differences in how much was assigned feed straight into the trajectories. Standardising within unit × class is the alternative to try.

Weak cluster structure

Average silhouette width is 0.36 for the 3-trajectory solution on model 1 / 3 states, in the 0.26–0.50 “weak structure” band, and 0.25 on model 2 / 4 states, just below it. Describe the trajectories as bands on a continuum rather than distinct types.

Story thread · Drops and recovery

The slide after unit 3 is the story’s drop, seen unit by unit, and the partial recovery in unit 12 matches the grade data: TE23’s late grade gains follow the final-project grade (ρ .91, Chapter 1). The class effect is the setting at work; Chapter 7 rebuilds te22a’s year lesson by lesson.

Step 0 · Event counts per unit

Every event gets a unit from its exercise, its notes page, or the page the student was on

TE22 events come from the 2023/24 log (Aug 2023–Jun 2024), TE23 events from the 2024/25 log between 1 Aug 2024 and 31 Jul 2025. 4,102 events were dropped: TE22 students' activity in the 2024/25 log, and TE23 activity after July 2025. Student and class come from the platform's id map; one te23b student in it has no events.

  • Exercises. The ID in /exercise/<id> or in exercise_id on autograde events is looked up in the exercise info. The unit is the first number of the name for course cs1-22: 515 exercises, units 1–12, with unit 12 holding the final project. Exercises from cs0 and cs2-22 count as another course.
  • Lesson notes. Notes IDs 2695–2945 are split into units by ID range. The ranges contain the collection IDs of every cs1-22 exercise in the matching unit. On notes_* events, exercise_id is the question number inside the page, not an exercise.
  • Everything else. The event takes the location of the student's last located event, if it was within 30 minutes. This covers file edits, inline runs, errors in 2023/24, resets and settings. A second, independently written count reproduces all 47,736 student-unit cells.

Step 1 · Variables → states

Activity per unit is one continuum, and LPA cuts it where the tails are

Indicators. Four raw counts per student and unit: code runs (run_code_exercise), code edits (file_edit), page views (pageview), and lesson-notes work (notes_correct + notes_incorrect + run_code_inline). Each is z-scored within unit × class, so differences in how much each class worked in a unit do not set the state scale.

Models. mclust 6.0.1, which tidyLPA calls: models 1, 2, 3 and 6 (EEI, VVI, EEE, VVV), with 1–8 profiles and mclust's default start. Model 3 leaves profiles empty from 5 profiles up. Model 6 has the lowest BIC but entropy of only 0.51–0.74. That leaves models 1 and 2.

Added 23 Oct 2026 · trajectories of mastery, persistence and self-regulation

Trajectories on social cognitive theory's features

The trajectories above are built from how much students do. Here the states come from how they work instead, from five features of Chapter 2, one or two per family of social cognitive theory: point completion (mastery experience), the error quotient and recovery at the next run (persistence), the share of work done outside lessons (self-regulation) and standing in the class (social comparison). Each is compared with the other students on the same unit. A unit without activity is a state of its own. The analysis covers units 1–10, because many final projects are built off the platform, and leaves out the three students with fewer than 20 active days in those units. That leaves 150 students.

Four states emerge: mastering (high completion and standing, few errors, more work outside lessons), average, recovering (few errors and quick recovery, but lower completion) and error-prone (repeated errors, slow recovery, low standing). The quality indices split evenly between two and four trajectories. With two, a group of 32 students stays in the mastering state through the course, 69% of their units, and is never error-prone; everyone else moves between the other states. With four, the rest separate into an average, an error-prone and a recovering trajectory.

These trajectories go with self-efficacy as well as with the grade. With two, the order of the trajectories goes with the final grade (ρ .37 [.21, .51]) and with self-efficacy (ρ .24 [.05, .41]). The activity trajectories show a less consistent self-efficacy link across definitions. With four, the error-prone trajectory has the lowest grades and self-efficacy, and the recovering one reports more self-efficacy than its grades alone would suggest. How students work, not only how much, separates the trajectories that go with the belief. Exploratory: the features were chosen with the same students' results in view, and self-efficacy was measured after the course.

Added 23 Oct 2026 · against the survey

Do the trajectories match goals, help seeking and habits?

A plan fixed in advance (20 Oct 2026) tested whether the activity trajectories, standardised within each class, go with what students report in the 2025 survey: self-efficacy, interest and future goals, trying to solve problems themselves first, and working only when a project is due. They do not. The three shapes recur, but under that standardisation almost every student sits in the high trajectory, and none of the four links holds (self-efficacy ρ −.05, all Holm-adjusted p = 1).

The trajectories on social cognitive theory’s features (above) do go with the survey. The sustained-mastery trajectory goes with higher self-efficacy, stronger interest and future goals, and more programming projects in free time, and a little with less help from others. That comparison was not planned in advance: read it as a lead. How much students do, relative to their class, says little about their goals or habits; how they work does. n = 92 with the survey. Answers are used only with consent; the survey was answered after the course.

Methods and limits

Decisions behind these numbers

  • Classes come from the platform's id map: te22b and te22c each have their own range of user IDs.
  • States are numbered from lowest to highest mean activity and named by rank: Low, Medium, High (Very low and Very high for 4 and 5 states). The Low state of model 1 is almost all zero-activity units; the names describe rank, not size.
  • Consensus trajectories: Ward was run on 500 random row orders. For each pair of students the share of orders that put them in the same cluster was counted, and an average-linkage tree was cut on 1 minus that share. Membership confidence is a student's mean co-assignment with the rest of their trajectory.
  • Quality statistics (PBC, HG, HGSD, ASW, ASWw, CH, R2, CHsq, R2sq, HC) follow WeightedCluster and come from the port in the Python package sequenzo 0.1.42. ASW, CH and R2 match an independent implementation exactly.
  • Sequence indices: transitions, entropy, complexity, volatility and integrative capacity follow TraMineR's definitions, with the highest state as the positive state. They were checked against sequenzo. Precarity follows seqprecarity's defaults (TRATEDSS, otto 0.2, a 1, b 1.2, states ordered from highest to lowest) in a re-implementation of TraMineR's, so treat it as approximate.
  • Discriminating subsequences are an approximation of seqefsub / seqecmpgroup: the start state plus one event per state change, ordered pairs up to length 2, support ≥ 5%, χ² across trajectories.
  • Software: R 4.3.3 with mclust 6.1.2; Python with pandas, SciPy, scikit-learn and sequenzo. Code and notes are in the project's analysis repository (private; available on request).
  • Consent: students who declined the use of their CS Academy data are left out: 153 students remain.
